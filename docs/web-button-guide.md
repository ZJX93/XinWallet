> 适用于 `public/` 下所有页面与 `public/js/managers/` 动态渲染的按钮。
> 确立时间：2026-09-04 / 提交 `757a48b`。
> 配套文件：`public/css/tokens.css`、`public/css/styles.css`、`public/css/login.css`。

## 1. 分级规则

按钮按语义分三级，**不要按页面或心情选样式**：

| 级别 | class | 视觉 | 适用动作 |
|------|-------|------|----------|
| 主操作 | `btn btn-primary` | 淡棕实心（奶茶色） | 保存、确认、新增、生成、导入、解析、记账、登录、检查更新 |
| 次要操作 | `btn btn-ghost` | 透明底 + 浅色描边 | 取消、关闭、✕、刷新、编辑、明细、重新选择、弃置、退出、测试连接 |
| 危险操作 | `btn btn-danger` | 红色实心 | 删除、清空并导入、禁用 |

原则：**一组按钮里最多一个主操作**。同一行出现两个淡棕实心按钮，说明分级错了。

### 1.1 主操作清单（现状）

新增交易 / 新增账户 / 新增分类 / 新增理财类型 / 新建标签 / 新增账本 / 添加预算 /
添加服务商 / 新增持仓 / 新建目标 / 生成报表 / 检查更新 / 立即更新 / 解析 /
识别并解析 / 解析账单 / 确认并记账 / 全部导入为交易 / 存入 / 还款 / 收款 /
合并导入 / 登录

### 1.2 次要操作清单（现状）

取消 / 关闭 / ✕ / 刷新 / 一键刷新 / 编辑 / 明细 / 记录 / 重新选择 / 弃置 /
退出 / 测试连接 / 测试 OCR / 查行情 / 取回 / 使用演示账号登录

## 2. 颜色 Token

主操作配色一律走语义 token，**禁止在按钮规则里写死色值**，改色只改 `tokens.css`：

| Token | 亮色 | 暗色 | 用途 |
|-------|------|------|------|
| `--interactive-soft` | `accent-200` = `oklch(82% 0.08 60)` | `oklch(46% 0.06 60)` | 主操作填充 |
| `--interactive-soft-hover` | `accent-300` | `oklch(53% 0.07 60)` | hover |
| `--interactive-soft-active` | `accent-400` | `oklch(60% 0.08 60)` | active |
| `--text-on-soft` | `oklch(28% 0.05 60)` | `oklch(95% 0.015 60)` | 主操作按钮上的文字 |

> **暗色为什么另取值**：亮色的 `accent-200` 明度 82%，直接用在深色背景上会过曝刺眼，
> 因此暗色主题改用中低明度暖棕填充 + 亮色文字，观感上仍是「淡棕实心」但与暗背景协调。
> 新增主题时必须同时补这 4 个 token。

主品牌色 `--interactive-default`（`accent-400`）保留给链接、图标、选中态、
焦点环等强调场景，**不再用于按钮填充**——按钮用比它更淡的 `--interactive-soft`。

## 3. 表单 submit 自动继承机制

全站 `form-actions` 有一个稳定约定：

- 主操作（保存 / 确认 / 提交）是 `type="submit"`
- 紧邻的「取消」是 `type="button"`
- 两者 class **完全相同**

因此 `styles.css` 用属性选择器自动区分，无需逐页手写 `btn-primary`：

```css
.btn.btn-ghost[type="submit"]:not(.btn-danger),
.btn[type="submit"]:not(.btn-ghost):not(.btn-danger) { /* 淡棕实心 */ }
```

**新增表单时**：主操作写 `type="submit"`、取消写 `type="button"` 即可自动获得正确样式。
若某个 submit 按钮确实要保持浅色，显式加 `btn-danger` 或改成非 submit 触发。

> 为什么用选择器而不是逐处改 class：历史上按钮风格改造靠逐个页面替换 class
> （见 `91b9ecc`），结果新增功能时反复漏改、风格漂移。选择器让约定自我维持。

## 4. 已知陷阱

### 4.1 `styles.css` 有两套按钮定义

`styles.css` 第 4 节（约 436 行）是 BUTTONS 主定义，但**文件末尾（约 2454 行）
还有一套重复的 `.btn` / `.btn-primary` / `.btn-ghost` 定义**。两者选择器优先级相同，
后出现者胜 —— 只改第 4 节不会生效。

**改按钮样式必须两处同步维护。**

### 4.2 登录页有独立覆写

`public/css/login.css` 另有一套 `.btn-primary` / `.btn-ghost`（按钮高度 44px，
与主站 38px 不同）。改主操作配色时需同步此文件，否则登录页会与全站脱节。

### 4.3 `data.js` 用的是另一套命名

`public/js/managers/data.js` 里行内操作按钮用 `btn-ghost-sm btn-text-sm`，
**不带 `btn` 基类**，不受上述 `.btn` 规则影响，需单独处理。

## 5. 自查清单

新增或修改按钮后确认：

- [ ] 按语义选了正确的分级（主 / 次 / 危险），一组内只有一个主操作
- [ ] 没有在 CSS 里写死颜色，只引用 token
- [ ] 亮色与暗色主题都看过（暗色下淡棕不应过曝）
- [ ] 改样式时 `styles.css` 两处定义已同步
- [ ] 涉及登录页时 `login.css` 已同步
